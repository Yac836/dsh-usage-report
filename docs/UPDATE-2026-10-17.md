# 费用提示与刷新修正：2026-10-17

本次继续更新草稿 PR #1，仅完善费用说明、刷新行为和相关失败提示。
不新增自定义价格、历史账单、数据库、依赖或配置项；没有部署、重启或改动实际 DSH 数据。

## 行为变化

| 场景 | 更新前 | 更新后 |
|---|---|---|
| 费用展示 | 容易被理解为实际花费 | 中英面板和命令均明确为当前目录估算，提示账单差异和历史估算变化 |
| 未定价模型 | 金额零占位容易被理解为免费 | 明确未知费用未计入合计、并非免费、合计可能偏低 |
| `/usage` 已有快照 | 可能直接返回旧报告 | 等待本次聚合，或共享同区间进行中的任务；失败明确报错 |
| 面板刷新完成 | 停止继续检查 | 可见时低频检查，隐藏暂停，恢复可见时检查 |
| 后台刷新失败 | 异常被吞掉，可能无限轮询 | 保留旧报告和时间并提示失败；无报告时返回 503；等待显式重试 |
| `ttlMs=0` | 每次进度查询可能又触发聚合 | `poll=1` 查询已有任务结果，不重新验证已有快照 |
| 切换区间失败 | 可能残留前一区间数据 | 清除不属于当前区间的报告并提示失败 |
| 金额/读取提示遗漏 | JSON 缺少币种回退标记，空报告隐藏读取失败 | 补充 `money.fellBack`，空报告也显示读取失败警告 |

`refreshAfterMs` 是报告响应中的常规检查间隔，按现有 `ttlMs` 限制为 30 秒至 1 小时。
任务执行中每 1.5 秒查询进度；失败后停止自动重试，刷新/重试按钮使用 `force=1`。
卸载组件会取消请求并清理计时器与可见性监听器。没有常驻全局轮询或新的运行服务。
